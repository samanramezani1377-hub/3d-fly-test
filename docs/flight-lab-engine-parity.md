# Flight Lab: shared training engine

## Source of truth

The browser Flight Lab does **not** contain a second JavaScript implementation of flight dynamics. It loads the Python package from `training/fast_physics/` and runs it in Pyodide (WebAssembly).

The browser bridge in `site/engine.py` instantiates the same class used by training:

- `training.fast_physics.vehicle_family.VehicleFamilyEnv`
- `training.fast_physics.env.AdaptiveDroneEnv`
- `training.fast_physics.dynamics.FastQuadrotor`
- `training.fast_physics.parameters.VehicleParameters`
- `training.fast_physics.system_identification.OnlineThrustEstimator`
- `training.fast_physics.curriculum.randomization_for_stage`

It also loads the same family profile and domain-randomization JSON files as training.

## Runtime contract

- Action: four normalized rotor commands, shape `(4,)`, clipped by the same environment to [0, 1].
- Physics step: `dt=0.02 s` (50 Hz), advanced by a fixed-step accumulator independent of display refresh rate.
- Episode horizon: 1500 steps.
- Observation: generated by `VehicleFamilyEnv`; the current family schema is 4 history frames × 16 values + 2 estimator values + 12 vehicle features = 78 values.
- Randomization: same `domain_randomization.json`, with optional curriculum stages 1–5.
- Seed: passed to `VehicleFamilyEnv.reset(seed=...)` for reproducible episode sampling.

## What this verifies—and what it does not

The browser and PPO training now call the **same Python environment and dynamics source**, so there is no independent browser physics port to drift away from training.

The current web UI sends manual four-motor actions. It does not yet load or execute a trained PPO checkpoint. Therefore this page validates and visualizes the training environment, action interface, observations, randomization, estimator, rewards and termination behavior; it does not by itself validate a learned policy or prove that a PPO checkpoint has learned to fly.

The Pages workflow publishes the Python package alongside the static UI. Pyodide and Gymnasium are loaded in the browser, so the first load requires internet access to their CDN/package sources.

## Calibration warning

The vehicle family profiles are marked provisional. Sharing code guarantees software-path parity, not physical accuracy. Real-world fidelity still requires measured mass, center of gravity, inertia, motor/propeller thrust curves, motor response, battery behavior and aerodynamic parameters.
